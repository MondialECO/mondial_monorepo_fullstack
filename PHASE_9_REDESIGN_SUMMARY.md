## What Changed From Old Design

### Data Model: 1 → 3 Collections
```
OLD: DealAgreement (nested TermSheet, Documents, Stakeholders, Milestones, Messages, CapTable)
NEW: Deals + TermSheets + DealTimelineEvents (flat, focused)
```

### State Machine: 10 → 5 States
```
OLD: initial → proposed → negotiating → loi_signed → legal_review → board_approved → investor_approved → closing → closed
NEW: interested → in_discussion → term_sheet → due_diligence → closed
```

### APIs: Restructured
```
REMOVED: propose-terms, status, messages, documents, abandon
ADDED: summary, timeline, term-sheets endpoints
SIMPLIFIED: UpdateDeal (single endpoint for all changes)
```

### Service Methods: 12 → 12 (but simpler)
```
Removed: cap table logic, stakeholder management, milestone tracking, document upload
Added: fire-and-forget timeline events, term sheet lifecycle
```

## State Machine Rules

**Valid transitions:**
```
interested → in_discussion | abandoned
in_discussion → term_sheet | abandoned
term_sheet → due_diligence (via AcceptTermSheet) | in_discussion (via CounterTermSheet) | abandoned
due_diligence → closed | term_sheet | abandoned
closed → (read-only)
```

**Term sheet actions auto-transition:**
- AcceptTermSheet → Deal.Status = "due_diligence", Deal.CommittedAmountEur set
- CounterTermSheet → Deal.Status = "in_discussion"

## Key Design Decisions

✅ **3 separate collections** (not nested)
- Better query performance
- Simpler indexes
- Easier to evolve separately

✅ **PostMoneyValuationEur always derived server-side**
- Post = Pre + Investment (immutable math)
- Never accept from client

✅ **Timeline events auto-generated**
- Fire-and-forget (non-blocking)
- Replaces over-engineered Milestone tracking
- Matches Figma visual design

✅ **5 states matching Figma tabs**
- interested | in_discussion | term_sheet | due_diligence | closed
- Simpler than 10-state machine

✅ **No cap table, stakeholder, or document logic**
- Post-MVP features
- Matches Figma scope
